## Зависимости

с++17
qt5.15
qmake
googletest

## Кодировка

Для всех файлов использовать кодировку UTF-8 без BOM.

## Правила написания кода

Подкаталоги
- 3rdparty  ->Вспомогательные библиотеки
- src       ->Исходные тексты
- resources ->Ресурсы (картинки, звуки,переводы, шрифты, порно)

2. Файлы.
В одной паре файлов (*.h и *.cpp) по возможности описывается только один класс.
В файле «*.h» - объявление, в «*.cpp» - реализация.
Если нет необходимости описывать реализацию отдельно от объявления (например если все функции указаны как inline, либо это
описание интерфейса и т. п.), то использовать для этих целей один файл с расширением «*.hpp».

### 3. Классы и структуры.
Имена структур, классов и перечислений должны начинаться с заглавной буквы (Пример: VideoStreamTest).

Использовать структуры (struct) только для хранения данных, недопустимо реализовывать поведение.

Доступ к полям структуры должен быть прямым, без «get»/«set» полей.

Методы могут использоваться только для создания или проверки данных (конструктор, деструктор, init(), validate()).

### 4. Классы

Перед классом всегда добавлять описание класса, алгоритм его работы и примеры использования.

### 4.1 Члены и методы класса.

Все члены класса должны быть private.
Использовать верблюжий стиль записи имен членов и методов.
Имена членов класса начинать с префикса «m_».
Доступ к ним должен осуществляться через функции «get»/«set».

Имя const или static const поля, находящегося в единице трансляции и не входящего в структуру/класс/функцию, начинать с префикса «k_».

Глобальные переменные и функции выделять в отдельный файл global.h, global.cpp.

### 4.2 Лямбда функции

Не использовать лямбда функции.

### 4.3 auto

Запрещено использовать ключевое слово auto везде, кроме случаев когда без него не обойтись.

### 4.4 Qt

Для сигналов и слотов использовать префиксы signal_ и slot_.
Порядок секций: signals — public slots — private slots.

### 5. Порядок объявления сущностей класса

Объявление класса должно начинаться с секции public, затем protected, затем private.

### 6. Требования к коду

Проверять входные параметры, не использовать C-style cast, использовать const где возможно.

### 7. Пробелы и комментарии

Использовать Doxygen комментарии для классов и методов.
